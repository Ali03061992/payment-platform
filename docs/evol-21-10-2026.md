# NEXTERA — Évolutions du 21/10/2026

> Périmètre : QR codes JSON sur les documents métier, pages de détail par type, parcours litiges, chatbot et interrupteurs fiscaux TEIF/TEJ côté fournisseur.
> Tests : UI 1101/1101, backend 575/575 (0 échec).

## 1. QR codes JSON et scanner

Tous les documents métier embarquent désormais le même format de QR :

```json
{"v":1,"type":"ORDER","reference":"CMD-2026-0001"}
```

| Type | Document |
|---|---|
| `ORDER` | Bon de commande |
| `INVOICE` | Facture |
| `QUOTE` | Devis / demande de devis |
| `DELIVERY` | Livraison |
| `PAYMENT` | Paiement |
| `DISPUTE` | Litige |
| `WITHHOLDING_CERTIFICATE` | Certificat de retenue (TEJ) |

- Backend : `DocumentQrPayload.of(type, reference)` (Jackson, `LinkedHashMap` → sérialisation déterministe).
- UI : `core/document-qr.ts` — `documentQrData()`, `parseDocumentQr()`, `documentQrRoute()`.
- Scanner : le JSON est reconnu en priorité ; repli sur les anciens formats `FACTURE:…`, `DOC:…`, `TEJ:CERT:…` pour les documents déjà imprimés.
- Navigation après scan :

| Type | Route |
|---|---|
| `ORDER`, `DELIVERY` | `/dashboard/orders/:reference` |
| `INVOICE` | `/dashboard/invoices/:invoiceNumber` |
| `QUOTE` | `/dashboard/quotes/:reference` |
| `PAYMENT` | `/dashboard/payments/:reference` |
| `DISPUTE` | `/dashboard/disputes/:id` |
| `WITHHOLDING_CERTIFICATE` | `/dashboard/certificates/:number` |

## 2. Pages de détail documents (UI)

Nouveaux composants `documents/` : `order-document`, `invoice-document`, `quote-document`, `certificate-document`. Chaque page charge la donnée par référence/numéro, affiche le QR régénéré et propose les actions existantes (téléchargements PDF, XML, etc.).

- `invoice-document` : chargé via `GET /api/organizations/orders/invoices/{invoiceNumber}`.
- `order-document` : chargé via `GET /api/organizations/orders/reference/{reference}`.
- `quote-document` : chargé via `GET /api/organizations/quotes/requests/reference/{reference}`.
- `certificate-document` : chargé via `GET /api/organizations/orders/withholding-certificates/number/{number}`.
- `payment-detail` : QR = `documentQrData('PAYMENT', reference)`, partage basé sur `window.location.origin`.
- Boutiques et fournisseurs : bouton « Bon de commande » (`GET /{id}/purchase-order`) et QR JSON sur `order-detail` / `order-management`.

## 3. Litiges

- Liste partagée tous rôles (`/dashboard/disputes`) : plus de filtre client, le périmètre est appliqué par le backend (`scope=own|all` selon le rôle) ; affichage de `orderReference` (repli sur les 8 premiers caractères de `orderId`).
- Détail (`/dashboard/disputes/:id`) : lien retour liste, référence de commande cliquable (`/dashboard/orders/:reference`), cartes boutique/fournisseur, navigation d'erreur vers la liste.
- Backend : `DisputeResponse` enrichi (`orderReference`, `supplierName`, `shopName`).
- i18n : `DISPUTES.BACK_TO_LIST`.

## 4. Chatbot

- Liens contextuels selon le rôle : commande → `/dashboard/orders/{reference}` (ou vue boutique), litige créé → `/dashboard/disputes/{id}`.
- Bouton « Recommencer » dans l'en-tête (`CHATBOT.RESTART`) qui réinitialise la conversation.

## 5. Interrupteurs fiscaux TEIF/TEJ (fournisseur)

- Colonnes `teif_enabled` / `tej_enabled` (défaut `TRUE`) — migration `V20__org_fiscal_feature_toggles.sql`.
- API : `GET|PATCH /api/organizations/settings` (réservé au fournisseur) expose et met à jour les deux indicateurs ; `OrderResponse` expose `supplierTeifEnabled` / `supplierTejEnabled`.
- UI : page `supplier/fiscal-settings` (`/dashboard/supplier/settings`, `NAV.FISCAL_SETTINGS`), gating des boutons dans `order-detail` et `order-management`.
- Sémantique : la consultation des documents existants reste toujours possible ; seule la génération est bloquée, avec HTTP 409 :
  - TEIF : « Le fournisseur a désactivé la génération des documents TEIF » ;
  - TEJ : « Le fournisseur a désactivé la génération des certificats de retenue (TEJ) ».
- `GetWithholdingCertificateUseCase` n'est plus porteur du contrôle (lecture libre) ; le contrôle est appliqué dans les endpoints PDF/XML (`OrderController`).

## 6. Backend — récapitulatif

- `DocumentQrPayload` + QR sur facture, bon de commande et certificat de retenue ; QR 72×72.
- Mise en page PDF facture compactée (une seule page pour le scénario de test) : `MIN_ITEM_ROWS` 5→4, mentions légales en ligne 7 pt gris, signatures resserrées.
- Nouveaux endpoints de consultation ciblée : facture par numéro, commande par référence, devis par référence, certificat par numéro.
- `InvoiceJournalRepository` / `QuoteRequestRepository` : recherches par numéro/référence.
