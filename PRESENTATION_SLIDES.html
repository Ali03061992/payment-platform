Cohérence Événementielle : Pattern Outbox

1. Mutation
UseCase exécute la logique métier + outbox.append(event) dans même transaction
2. Persistance
Écriture atomique dans outbox_events (event_id, type, payload JSON, aggregate_id)
3. Relay
@Scheduled(1s) lit 100 events non traités → RabbitTemplate.convertAndSend(exchange, routingKey)
4. Consommation
@RabbitListener + EventDeduplicator.markProcessed(eventId) (idempotence PK)
5. Notification
Création notifications pour les 2 parties (shop + supplier) selon event type

Flux Paiement + Notifications Temps Réel

1. Shop crée
POST /api/payments {shopId:3, supplierId:1, amount:500, currency:"EUR"} → PENDING
2. Event
payment.created publié sur payment.events → queue notification.payments
3. Notifications
2 notifs créées : Supplier org=1 "Nouveau paiement PAY-xxx 500 EUR" + User créateur "Paiement soumis"
4. Supplier confirme
POST /api/payments/{id}/confirm → payment.confirmed → notif shop "Confirmé par fournisseur"
5. Rejet / Annulation
payment.rejected (motif) → notif shop | payment.cancelled → notif supplier
